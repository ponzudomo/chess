# 初心者向け：デバッグと検証の完全ガイド

アプリを動かしていると、「思った通りに動かない」「画面が真っ白になった」ということが必ず起こります。
そんなときに原因を突き止め、直す作業を **「デバッグ (Debug)」** と呼びます。

このガイドでは、Web開発におけるデバッグの基本テクニックを、探偵の捜査になぞらえて解説します。

---

## 🕵️‍♀️ STEP 1: 事件現場を確認する（DevToolsのConsole）

Webアプリの不具合の9割は、ブラウザが「ここにエラーがあるよ！」と教えてくれています。
まずはそのメッセージを確認しましょう。

### 使い方
1. ブラウザ画面上で **右クリック** → **「検証 (Inspect)」** をクリック。
2. 開いたパネルの上部にある **「Console (コンソール)」** タブをクリック。

### 見るべきポイント
- **🔴 赤い文字 (Error)**:
  - **これが犯人です。** プログラムが動かなくなる致命的なエラーです。
  - 例: `Uncaught TypeError: Cannot read properties of undefined`
    - 翻訳: 「空っぽ（undefined）のデータの中身を見ようとして失敗したよ」
    - 対策: そのデータを使う前にデータが入っているかチェック (`if`) する必要があります。

- **🟡 黄色い文字 (Warning)**:
  - 「動くけど、書き方が古いよ」「これ忘れてない？」という注意書き。
  - 今すぐ直さなくても動きますが、後でバグの原因になることがあります。

---

## 📝 STEP 2: 捜査メモを残す（console.log）

エラーが出ていないのに動かないとき（例：「ボタンを押しても色が塗られない」）は、プログラムがどこまで動いているかを確認します。
そのための最強の道具が `console.log()` です。

### 基本的な書き方
確認したいコードの前後に、メモを挟み込みます。

```javascript
// 1. 関数が実行されたか確認する
console.log("① 攻撃範囲の計算を開始します");

const result = calculateAttack(board);

// 2. データの中身を確認する
console.log("② 計算結果:", result);
```

### どこに書く？
- **if文の中**: 「条件分岐のこっちに入ったかな？」を確認するため。
- **ループの中**: 「ちゃんと全ての駒をチェックしているかな？」を確認するため。
- **変数の下**: 「この計算結果は合っているかな？」を確認するため。

### VizChessでの実践例
今回の「色が塗られない」問題では、`src/components/Board/ChessBoard.tsx` に以下のようなログを仕込むと原因がわかります。

```typescript
// vizMode が 'board' になっていないのが原因かも？
console.log("現在のモード:", vizMode); 

// 計算した結果、配列が空っぽになっているかも？
console.log("計算された色塗り情報:", status);
```

**確認方法**: ログを書いたらファイルを保存し、ブラウザの「Console」タブを見てください。あなたの書いたメモが表示されているはずです。

---

## 🔍 STEP 3: 証拠品を調べる（Elementsタブ）

「計算は合っているはずなのに、画面に表示されない」ときは、見た目の設定（CSS）が間違っている可能性があります。

### 使い方
1. 「検証」ツールの **「Elements (要素)」** タブをクリック。
2. 画面のHTML（ページの骨組み）が表示されます。
3. 調べたい場所（例：チェスのマス目）の上で **右クリック → 検証** すると、その部分のHTMLがハイライトされます。

### チェックポイント
- **`style="..."`**: ここに色が設定されていますか？
  - 例: `background-color: rgba(255, 0, 0, 0.5)` と書いてあるのに見えないなら、透明度が高すぎるか、他の要素の下に隠れているかもしれません。
- **サイズ**: 要素のサイズが `0px` になっていませんか？

---

## 🛠️ 上級者の道具（React Developer Tools）

今のアプリは「React」という技術で作られています。
Chrome拡張機能の **「React Developer Tools」** を入れると、「Components」というタブが増え、デバッグが劇的に楽になります。

- **何ができる？**: 
  - `console.log` を書かなくても、今の `vizMode` や `fen`（盤面）の中身をリアルタイムで見ることができます。
  - 「Hooks」の中身（`useState` の値など）を直接書き換えて、動きを試すことができます。

---

## 💡 まとめ：デバッグの心構え

1. **エラー文を恐れない**: 英語で怖いかもしれませんが、そこには必ず答えがあります。エラー文をコピペしてAIに「これどういう意味？」と聞くのも手です。
2. **仮説を立てる**: 「たぶんここまでは動いているはず」と考え、`console.log` でそれを証明します。
3. **小さく試す**: 一気に直そうとせず、「まずはログが出るか」「まずは背景色が変わるか」など、小さな変更で反応を見ましょう。

まずはブラウザの「Console」を開く癖をつけるところから始めましょう！
